One static website, rebuilt for every client.

Edge, hosting, monitoring ...

A proof of concept for publishing static websites on Azure: plain HTML, CSS and JavaScript served from the edge, with nothing to run behind it.

Serve

Azure Front Door in front, with a web application firewall, TLS, custom domains and edge caching. The site itself is plain HTML, CSS and JavaScript on a Static Web App.

Deploy

Every change goes through a pull request with its own preview site, then ships with GitHub Actions or Azure Pipelines without a build step.

Watch

Availability tests from five regions, edge and firewall logs, alerts and a shared dashboard in every environment, from dev to production.

A pattern, not a shared platform.

This site shows a reusable approach for publishing static websites. Each deployment reuses the technical pattern only. Names, wording, domains, content and branding always come from the client.

Site content and infrastructure follow separate release paths, so a content change never needs an infrastructure release.

Every client gets its own

  • Repository
  • Azure subscription
  • Dev, QA, UAT, production
  • Domain
  • Deployment token
  • Monitoring and alerts
  • Branding
  • Content

How a change goes live.

Reviewed on a preview site before production, confirmed by monitoring afterwards.

  1. Edit

    Change the HTML, CSS or JavaScript in app/ on a branch.

  2. Review

    Open a pull request. It gets its own preview site, and reviewers approve it there.

  3. Deploy

    Merge to main. The pipeline uploads app/ to the Static Web App.

  4. Serve

    Front Door serves the new version through the firewall and caches it at the edge.

  5. Watch

    Availability tests and alerts confirm the site is up, fast and error-free.

Two ways to deliver.

Choose one per client. Both ship the same app/ folder to the same Static Web App. Infrastructure is released separately with Terraform.

A

GitHub + GitHub Actions

Source
GitHub repository with a protected main branch
Build
One job checks app/ is complete. Nothing is compiled.
Release
Azure/static-web-apps-deploy on every merge to main
Previews
A preview site per pull request, removed when it closes
Approval
Required reviewers on the pull request
Secret
AZURE_STATIC_WEB_APPS_API_TOKEN
File
.github/workflows/deploy-static-web-app.yml
B

Azure Repos + Azure Pipelines

Source
Azure Repos with branch policies on main
Build
Build stage checks app/ and publishes the site artifact
Release
Release stage deploys it with the AzureStaticWebApp task
Previews
A named preview per pull request, pr<id>
Approval
Reviewers, plus an approval check on swa-production
Secret
Secret variable in the swa-deployment group
File
azure-pipelines.yml

Seven rules the build keeps.

Edge first
Azure Front Door is the only public entry point.
Static presentation
The browser receives build-free HTML, CSS and JavaScript.
No backend
No servers, databases or APIs to run, patch or secure.
Separate environments
Dev, QA, UAT and production each have their own settings, state and subscription.
Watched by default
Every environment gets availability tests, alerts and a shared dashboard.
Independent delivery
Site content and infrastructure release separately.
No invented configuration
Values missing from source are verified in Azure or authoritative IaC.

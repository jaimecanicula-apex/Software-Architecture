One static website, open to approved guests.

Public, signed in, approved ...

Reachable from anywhere on the internet, but nobody sees a page until they sign in with Entra ID. External people are invited as guests, and only approved accounts get in.

Public

Azure Front Door with a web application firewall serves it worldwide. The Static Web App only accepts traffic that came through Front Door.

Signed in

Every visitor signs in with Entra ID first. External people are B2B guests, and only the approved users group gets past sign-in.

Watched

Availability tests from five regions, edge and firewall logs, alerts and a shared dashboard in every environment.

Built for approved external users.

External clients and partners are invited as B2B guests of the APEX tenant and sign in with their own work or Microsoft account.

Only members of the site's users group, or another approved group, get past sign-in. Everyone else is refused, including APEX accounts that were not approved.

Every site gets its own

  • Repository
  • Azure subscription
  • Front Door and WAF
  • Entra app registration
  • Approved users group
  • Deployment token
  • Monitoring and alerts

How a change goes live.

Reviewed on a preview site before production, confirmed by monitoring afterwards. Previews ask for sign-in too.

  1. Edit

    Change the HTML, CSS or JavaScript in content/public-signin-static-website/ on a branch.

  2. Review

    Open a pull request. Approved reviewers sign in to its preview site to check it.

  3. Deploy

    Merge to main. The pipeline adds the sign-in config and uploads the site.

  4. Serve

    Front Door serves it through the firewall; visitors sign in first.

  5. Watch

    Availability tests on the health page and alerts confirm the site is up.

Two ways to deliver.

Choose one per site. Both write the Entra sign-in config into content/public-signin-static-website/ before uploading it. Infrastructure is released separately with Terraform.

GitHub + GitHub Actions

Source
GitHub repository with a protected main branch
Build
Checks content/public-signin-static-website/ and writes staticwebapp.config.json
Release
Azure/static-web-apps-deploy on every merge to main
Previews
Preview site per pull request, sign-in required
Approval
Required reviewers on the pull request
Secrets
AZURE_STATIC_WEB_APPS_API_TOKEN_PUBLIC_SIGNIN, SWA_CONFIG_JSON
File
.github/workflows/deploy-public-signin-static-web-app.yml

Azure Repos + Azure Pipelines

Release

Reviewers, plus an approval check on swa-public-signin-production
Secrets

Seven rules the build keeps.

Edge first
Azure Front Door and its firewall are the only way in.
Sign in first
Every page except the health check needs an Entra ID sign-in.
Approved only
Only the groups assigned to the site get past sign-in.
Guests, not accounts
External people sign in as B2B guests with their own account; the site stores no passwords.
No backend
No servers, databases or APIs to run, patch or secure.
Watched by default
Every environment gets availability tests, alerts and a shared dashboard.
No invented configuration
Tenant, groups and domains come from the owners, not guesses.

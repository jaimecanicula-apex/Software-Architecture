One static website, private to APEX.

Private, signed in, watched ...

An internal website for APEX colleagues and contractors. It is reachable only from the APEX network, and everyone signs in with their APEX account. Share documents in the file library.

Private

Reachable only through a private endpoint on the APEX network. Public access is switched off, and nothing is exposed to the internet.

Signed in

Every visitor signs in with APEX Entra ID. Only the groups assigned to the site get in; everyone else in APEX is refused at sign-in.

Watched

A probe inside the network checks the site every five minutes. Logs travel over Private Link to alerts and a shared dashboard.

Built for internal users.

Internal users are anyone who signs in with APEX Entra ID: IT and business colleagues, people from APEX companies, and contractors.

External clients and users never reach this site. A site for them uses the publicly accessible design instead.

Every internal site gets its own

  • Repository
  • Azure subscription
  • Private network
  • Entra app registration
  • Allowed groups
  • Deployment token
  • Monitoring and alerts
  • Content

How a change goes live.

The same reviewed path as a public site, but every preview and release stays inside the APEX network.

  1. Edit

    Change the HTML, CSS or JavaScript in content/privately-accessible-static-website-with-storage/ on a branch.

  2. Review

    Open a pull request. Its preview site is private too, so reviewers open it from the APEX network.

  3. Deploy

    Merge to main. The pipeline adds the sign-in config and uploads the site.

  4. Serve

    Signed-in APEX users reach it through the private endpoint.

  5. Watch

    The in-network probe and alerts confirm the site is up.

Two ways to deliver.

Choose one per site. Both write the APEX sign-in config into content/privately-accessible-static-website-with-storage/ before uploading it. Infrastructure is released separately with Terraform.

Seven rules the build keeps.

Private by default
Public network access is off; the site answers only on its private endpoint.
Always signed in
Every page except the health check needs an APEX sign-in.
Least access
Only the Entra groups assigned to the site can sign in.
No backend
No servers, databases or APIs to run, patch or secure.
Separate environments
Dev, QA, UAT and production each have their own network, settings, state and subscription.
Watched from inside
Availability is measured from inside the network, and telemetry never crosses the internet.
No invented configuration
IP ranges, groups and DNS come from the APEX platform team, not guesses.
